# Pac-Man

A complete, playable recreation of the arcade classic pacman, written in python with an object oriented, modular architectur, Mazes are generated by an external A-Maze-ing package, the game is configured through a Json file with comments, ad the packaged build is distributed on itch.io.

## Description


**Goal:** Build a polished Pac-Man clone with a main menu, a game view and game over/victory handling, a simple graphics library (MLX/pygame) and no crash on any bad input.

- **`overview`**
    - At least 10 levels, each with a time limit, score and lives carry over between levels.
    - 4 ghosts `one per corner` that chase the player, flee when edible, and respawn after being eaten.
    - Pacgums in corridors based on the config and 4 super pacgums in the corners.
    - Presistent top-10 highscore table
    - chear mode for peer review
    - configurable through a JSOn file that suppot # comments
    - Mazes produced by an A-Maze-ing package from another group, used as is Game loop: Main menu -> Start game -> Win or lose -> Enter name -> Main menu

## Configuration

The configuration file is JSON with comments: lines starting with `#` are ignored.

Invalid or missing values are replaced by safe defaults (clamped), a clear message is logged, and the game continues. Unknown keys are ignored.

|Key|Type|Default|Description|
|---|---|---|---|
|`highscore_filename`|string|`highscores.json`|File where highscores are stored|
|`lives`|int|`3`|Starting lives|
|`pacgum`|int|`10`|_meaning as implemented_|
|`points_per_pacgum`|int|`10`|Score for a pacgum|
|`points_per_super_pacgum`|int|`50`|Score for a super-pacgum|
|`points_per_ghost`|int|`200`|Score for an edible ghost|
|`seed`|int|`42`|Seed for the level-1 maze|
|`level_max_time`|int|`90`|Time limit per level|
|`levels`|list|_10 levels_|Per-level settings, each with `width` and `height`|

Example:

```json
# Pac-Man configuration
{
  "highscore_filename": "highscores.json",

  "seed": 42,
  "level_max_time": 90,

  "lives": 3,

  "pacgum": 10,
  "points_per_pacgum": 10,
  "points_per_super_pacgum": 50,
  "points_per_ghost": 200,
  "level": [{"width": 11, "height": 7},
            {"width": 13, "height": 9},
            {"width": 15, "height": 9},
            {"width": 17, "height": 11},
            {"width": 19, "height": 11},
            {"width": 21, "height": 11},
            {"width": 21, "height": 13},
            {"width": 23, "height": 13},
            {"width": 25, "height": 13},
            {"width": 25, "height": 15}
            ]
}
```

# Highscore

the highscore iterface triggeres when ever the player is in lose or win condition enabling the player to save their score if it ranks within the top 10, if the player submit an empty field the system safely defaults to the name `PLAYER`

- Input Sanitization: The UI only accepts alphanumeric characters to prevent Json parsing errors
    
- Data integrity: Before rendering, the file passes through a recursive validation filter that explicitly checks data types and strips out corrupted entries or malicious injections like nested lists or negative scores
    
- Memory Protection: the system check the file size at the os level before locating ram, preventing the engine from crashing if a massive malicious edited file is loaded, capping the saved list to 10 entries ensures the file footprint remains small.

## Maze Generation

Mazes are generated by the A-Maze-ing package, it is used as is without modification

- A single adapter module maze.py is the only part of the code that talks to the package, our loader adapts to it's interface, not the other way around.
- Parameter `Perfect` is set to False to obtain Pac-man compatible corridors.
- Level 1 uses a fixed seed, every following level uses a random maze.
- the adapter converts the package's output into out internal grid/wall model and validates it.
- Any failure of the genrator is caught and reported cleanly without crashing the game.

## Implementation

### Architecture


- The project has two layers:
    - **Logic** (`src/logic`): maze adapter, entities, ghost AI, pacgum pacement, collision and scoring rules. it does no drawing.
    - **UI** (`src/UI`): window, screens, buttons, gameplay rendering, cheat mode and highscore screens. `Game` owns the window, clock, assets and dictionary of screens (Menu, Gameplay, Name_entry, HighScoreSreen), Every screen exposes update(events, dt) and draw(). update returns the name of the next screen or None, the main loop runs at 60 fps: it collects events once, handles the window close event, updates the active screen, applies any state change and draws, Buttons call thier callback with no arguments, so screen change use partial to bind the target state name.
- `Gameplay`
    - Grid Logic, smooth rendering: entities move one cell at a time, and the player sprite is interpolated between the previous and curret cell for drawing. cell coordiantes are converted to pixels witht hte cell size and centering offset.
    - Movement: the last pressed direction is queued and applied at the next move tick. if it's blocked the player keeps it's current irection, the player stays still until the first key press of a level or after a death
    - Time: the countdown used dt in second. Delays and ghost timers use milisecond game clock advanced by dt only while the gameplay screen updates, so pausing freezes every timer.
    - Spawn: the player spawsn in the miiddle of the maze. if that cell belongs to the 42 block a bfs finds the nearest open cell.
    - Levels: lives and score carry over. time, ghosts and pacgums reset ad each level abd a level eds when all pacgums are eaten.
    - Rnd conditions: time out, no lives, or all levels completed. EAch show it's own message on the name entry screen.
- `Ghosts`

Each ghost has a state and a color sprite, and is bound to one corner of the maze.

|Ghost|Corner|Chase behavior|
|---|---|---|
|Pink|Top-left|**Hunter:** takes the shortest path (BFS) to the player|
|Green|Top-right|**Wanderer:** random direction, avoids turning straight back|
|Red|Bottom-right|**Wanderer:** random direction, avoids turning straight back|
|Yellow|Bottom-left|**Shy:** chases by shortest path, but retreats to its corner when the player gets within 8 cells, and resumes once the player is more than 10 cells away|
### Cheat mode

Shift plus a key, read from key-down events so each press counts once. Active cheats appear in the HUD and are cleared when a new game starts.

|Key|Effect|
|---|---|
|Shift+L|+1 life|
|Shift+N|skip to the next level|
|Shift+I|toggle invincibility|
|Shift+F|freeze ghosts|
|Shift+V|toggle speed boost|

## General Software Architecture

The project has two layers: **logic**, which never draws, and **UI**, which handles the window and rendering.

```
pac-man.py              entry point: reads the config and starts the game
src/
├── config_loader.py    ConfigLoader: JSON-with-comments parsing, validation, defaults
├── resources.py        resource_path(): asset lookup (source or PyInstaller bundle)
├── logic/
│   ├── maze.py         MazeLoader: adapter to the A-Maze-ing package + wall test
│   ├── entities.py     Entity (position, direction, movement) and Player (score, lives, spawn)
│   ├── ghost.py        Ghost (extends Entity): states, pathfinding and per-ghost AI
│   └── game_state.py   GameState: pacgum placement, collisions, scoring rules
└── UI/
    ├── Game.py         Button and Game: window, assets, screens, main loop
    ├── Gameplay.py     Gameplay, Name_entry, HighScoreScreen
    └── menu.py         Menu: generic screen made of a background, images and buttons
img/                    sprites, backgrounds and font
project_management/     project management documents
```

**How the pieces relate**

- `pac-man.py` creates a `MazeLoader`, a `GameState`, and the config (via `ConfigLoader`), then hands all three to `Game` and calls `run()`.
- `Game` owns the window, clock, assets, and a dictionary of screens (`Menu`, `Gameplay`, `Name_entry`, `HighScoreScreen`). Every screen exposes `update(events, dt)` and `draw()`. `update` returns the name of the next screen, or `None` to stay.
- The main loop runs at 60 FPS: it collects events once, handles the window-close event, updates the active screen, applies any state change, then draws.
- `Button` calls its callback with no arguments, so screen changes use `functools.partial` to bind the target state name.
- `Gameplay` uses `MazeLoader` to build each level, creates a `Player` and four `Ghost` objects, and delegates placement, collisions, and scoring to `GameState`.
- `Player` and `Ghost` both inherit from `Entity`, which handles wall-checked movement through `MazeLoader.can_move()`.
